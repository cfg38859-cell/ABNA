# چطور برنامه را تغییر بدهیم

## قاعدهٔ طلایی
برنامه به قطعه‌های کوچک شکسته شده تا **فقط همان قسمتی که عوض می‌شود** ویرایش شود، نه کل برنامه. مثلاً:

| تغییر | فایل |
|---|---|
| اصلاح حضور و غیاب هیئت | `src/js/main/10-attendance.js` |
| امور مالی، PDF ایستگاه | `src/js/main/20-finance.js` |
| انتقاد و پیشنهاد | `src/js/main/30-suggestions.js` |
| موارد انضباطی | `src/js/main/40-discipline.js` |
| دعوت مداحان | `src/js/main/50-invitations.js` |
| اعضا، پشتیبان، تم، آکادمی، گزارش‌ها | `src/js/main/60-core-members-backup-themes.js` |
| ایستگاه صلواتی (بخش مستقل) | `src/js/07-station-section.js` |
| ظاهر | `src/css/*.css` |

## چرخهٔ معمول
```bash
npm run dev                  # ویرایش و دیدن نتیجه روی http://localhost:8080
npm test                     # سلامت
node build/bump.mjs          # فقط وقتی نسخهٔ جدید می‌دهید
git commit -am "توضیح"
git push                     # Pages و APK خودکار ساخته می‌شوند
```

## شماره نسخه و بخش «به‌روزرسانی» برنامه
- `APP_VER` (در `src/js/02-self-update-loader.js`) همان عددی است که بخش «به‌روزرسانی» با آن مقایسه می‌کند: فقط فایلی با نسخهٔ **بزرگ‌تر** نصب می‌شود.
- پس هر بار رفتار برنامه عوض شد، نسخه را بالا ببرید: `node build/bump.mjs`.
- اگر کسی نسخه‌ای از طریق بخش «به‌روزرسانی» نصب کرده باشد، آن نسخهٔ ذخیره‌شده تا وقتی نسخهٔ داخلی بزرگ‌تر نشود اولویت دارد.
